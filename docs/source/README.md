# Project documentation sources

These files produce `docs/WoredaCare_Project_Documentation.pdf`, the industrial project
documentation that follows the Kotebe University of Education guideline (Chapters 1 to 8).

| Path | Content |
|---|---|
| `content-1.html` | Chapter 1 (Project Proposal) and Chapter 2 (Requirement Analysis Document) |
| `content-2.html` | Chapters 3 to 8 (SDD, ODD, Implementation, Conclusions, References, Appendices) |
| `fig/` | Diagrams as SVG (generated by `tools/diagrams.mjs` and `tools/subsystems.mjs`) |
| `img/` | Screenshots of the running system with sample data |
| `tools/build.mjs` | Builds the PDF; also holds the cover page and the list of abbreviations |

## Fill in the placeholders

Text the software cannot provide is marked `<span class="ph">[ ... ]</span>` (highlighted in the
PDF). Replace each placeholder with the real information:

- Cover page (team members, IDs, advisor, faculty, department, date): in `tools/build.mjs`, `frontHtml`.
- Field data on the current process: Sections 1.1.1, 1.6.1 and 2.2 in `content-1.html`.
- Semester dates and weeks 10 to 16: Section 1.8 in `content-1.html`.
- Production hardware and hosting: Section 3.3.1 in `content-2.html`.
- Usability test results: Section 5.2.3 in `content-2.html`.
- Guideline reference details: Chapter 7, reference [1], in `content-2.html`.

Appendix D in the PDF lists the same items.

## Rebuild the PDF

Requires Node.js 22 or later and Google Chrome at `/usr/bin/google-chrome`.

```bash
cd docs/source/tools
npm install          # puppeteer-core, mermaid, pdf-lib (not committed)
npm run build        # writes docs/WoredaCare_Project_Documentation.pdf
npm run diagrams     # only if a diagram source in diagrams.mjs or subsystems.mjs changed
```

The build numbers figures and tables per chapter, inserts the diagrams, and fills the table of
contents and the lists of figures and tables with the real page numbers.

`seed.mjs`, `seed2.mjs`, `shots.mjs` and `shots2.mjs` recreate the sample data and screenshots
against a disposable database and a locally running API (port 18080) and client (port 5173).
